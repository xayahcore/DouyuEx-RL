## 0. 先回答你的两个质疑

### 0.1 "你就是把中间那层嵌套加回来，然后给每个面板套上"

**成立。** 我上一轮做的确实是"给旧结构套新皮"，证据在我自己的改动里：

- 我新增的是 **CSS 别名组**：把 `.fans-panel__card / .popup-panel__card / .exupdate-panel__card / .livetool__cell` 写进同一条规则，让它们"看起来一样"；
- 但 **DOM 一点没动**：八个面板仍然各写各的模板字符串、各用各的类名、各自内联样式；
- 更糟的是，为了让"非行式内容"（版本更新正文、直播间工具的行）也有白底，我又**给卡片本身加回了白片** —— 于是层数从"托盘+行"变成"托盘+卡片+行"，正是你说的"中间态嵌套加回来"。

一句话：**统一发生在 CSS 层，没发生在 DOM 层**。真正的统一必须让八个面板产出**同一种 DOM**，样式才有意义。

### 0.2 "你是不是回退到上一个版本了？Dock 选中白底、三级菜单白底又回来了"

**没有回退到任何 commit**，但你的观感是对的 —— 原因有两个，第二个是本质：

1. **可能是旧会话**：我留着几个 ego 空间（`dyex-g2-local`/`-unify3`/`-final`），它们注入的是**当时那版 bundle**。如果你在看早期那个空间，看到的就是旧样式。
2. **本质原因（这条要改）**：现在是 **两层白叠着** ——
   - 托盘 `rgba(255,255,255,0.34)`
   - 白片 `rgba(255,255,255,0.42)`
   - 叠出来的有效白 = `1-(1-0.34)(1-0.42) = 0.617`

   数值上"刚好够读"，但**视觉上是两层**：卡片是一块白，行又是一块白，Dock 磁贴又是一块白。你看到的"白底回来了"就是这 0.617 的两层叠加，不是某个 commit 被回退。

**关键结论**：把托盘改成**不着色**、白片提到 `0.62`，有效白还是 `0.62`（≈原来的 0.617，对比度几乎不变），但**只剩一层白**。数值不变、结构变了 —— 这就是"从底上统一"的判据。

## 1. 目标与不变式（Invariants）

> 下面 7 条是可机械校验的，任何一条不满足 = 方案没落地。

| 编号 | 不变式 | 怎么校验 |
|---|---|---|
| **I1** | **全站只有一层白**：玻璃托盘 alpha=0（只有 blur），白片是唯一的半透明白 | 读计算样式：托盘 bg 必须 `rgba(0,0,0,0)`；白片家族只有 `--miuix-item-bg` 一个值 |
| **I2** | **一个角色只有一条规则**（仓库测试已强制其中两项） | `tests/test_built_bundle.js` 场景 11/12 扩展 |
| **I3** | **面板 DOM 只能由 `ExUI.*` 产出**，不再出现 `fans-panel__card` 这类自带样式的类名 | grep 源码：旧类名计数只减不增 |
| **I4** | **面板内禁止内联 style**（颜色/字号/间距） | grep `style="` 计数归零（分批次） |
| **I5** | 文字永远坐在白片上：任何文本节点的最近背景必须是白片或磁贴 | 逐面板实测对比度 ≥4.5:1（黑/暗/亮/白四帧） |
| **I6** | 红线：`380px`/`370px` 全产物各 1 次；包级 CSS 不定义 8 个面板类名；`ExSave_` 前缀；DOM 判空 | build 门禁 + grep |
| **I7** | 改动可回滚：视觉层单文件、组件层单文件、每批单独 build+test | git 粒度 + 预览台对照 |

## 2. 视觉架构 v3（最终形态）

### 2.1 三层语义，只一层是白

| 层 | 取值 | 谁在上面 | 最坏帧（纯黑）对比 |
|---|---|---|---|
| **托盘**（面板本体 / Dock 胶囊） | `background: transparent` + `backdrop-filter: blur(28px) saturate(200%)` | 什么都没有（只有模糊后的画面） | — |
| **白片**（行 / 正文块 / 面板头 / Dock 磁贴 / 空状态） | `rgba(255,255,255,0.62)` + `1px solid rgba(255,255,255,0.55)` | 所有文字与控件 | `#0f172a` 6.66 / `#1e293b` 5.46 / 蓝药丸白字 4.83 |
| **墨**（3 档 + 蓝） | `#0f172a` / `#1e293b` / `#475569`（仅不透明底）/ 蓝 `#0066ff` 只做填充 | — | — |

> 为什么白片是 0.62 而不是 0.42：托盘不再贡献白，白片必须自己撑起 4.5:1。**0.62 与现在的 0.617 等价**，所以观感不会变淡，只会从"两层"变"一层"。

### 2.2 Dock 与面板用同一块白

磁贴、面板头、子项行、正文块、空状态 —— 全部 `--miuix-item-bg`。**没有第二档白**。
选中态：**不变白**，只靠「图标填色 + 底部指示条 + 2px 上浮」；hover：白片提到 0.74，不加边框颜色（避免"选中/悬停"再次混淆）。

### 2.3 深色（D2，已算过）

托盘：`rgba(16,20,26,0.18)` + `blur(30px) brightness(0.45)`；白片换成"深片" `rgba(16,20,26,0.14)`（等效 0.30，透光 70%）。
墨：`#ffffff` / `#e2e8f0` / `#cbd5e1`；蓝 `#7db0ff` 只做图形。最坏（纯白画面）6.83 / 5.96 / 4.95 / 3.33 全过。

### 2.4 主题三态（白天 / 黑夜 / 跟随）

- 存储：`ExSave_theme` = `light|dark|auto`
- 生效：`html[data-dx-theme]` + `[data-dx-theme-mode]`，样式只认这两个属性
- 「跟随」= **纯 CSS 属性选择器** `html[data-mantine-color-scheme="dark"][data-dx-theme-mode="auto"]`（零 JS、免疫斗鱼 5s 回落）+ JS 只负责磁贴图标与 aria
- 判据顺序按取证：页面属性 → cookie 的 auto 折算 → body 亮度(<0.2) → `prefers-color-scheme`
- 可选联动：写 `mantine-color-scheme-value` + 派发 `StorageEvent`（实测 400ms 免刷新生效）

## 3. 组件体系（真正从底上统一）

### 3.1 `ExUI` 构造器（唯一出口）

| API | 产出 DOM | 用途 |
|---|---|---|
| `ExUI.card({title, aside, body})` | `section.ui-card > .ui-card__head(.ui-card__title/.ui-card__aside) + .ui-card__body` | 分组，不刷白 |
| `ExUI.row({title, desc, control})` | `label.ui-row > .ui-row__text(.ui-row__title/.ui-row__desc) + 控件` | 一条设置项 = 一块白片 |
| `ExUI.prose(html)` | `div.ui-prose` | 长正文（版本更新）= 一块白片 |
| `ExUI.empty(text)` | `div.ui-empty` | 空状态 = 一块白片 |
| `ExUI.btn(text, {variant})` | `button.ui-btn.ui-btn--{primary|quiet|danger}` | 三档按钮 |
| `ExUI.seg(...)` / `ExUI.field(...)` | `div.ui-seg` / `label.ui-field` | 互斥单选 / 输入行 |

样式侧：**每个 `.ui-*` 角色只有一条规则**，全部写在 `ExPanel.css`（遵守"UI 改动归口"红线）。

### 3.2 迁移矩阵（八面板 → 组件）

| 面板 | 现在的类名 | 目标 | 迁移量 |
|---|---|---|---|
| 一键签到 | `fans-panel__card` + `sign-option-item` | card + row | 中（首个试点） |
| 一键续牌 | 同上 + `asset-item`/`badge-row` | card + row + `ui-stat` | 中 |
| 扩展功能 | 同上 + 内联样式 **30 处** | card + row + `ui-btn` | **最大** |
| 弹幕发送小助手 | `bloop__*` **52 处** + 7 处内联 | card + row + field + seg | 大 |
| 直播间工具 | `livetool__cell` + span 假按钮 | card + row + btn | 中 |
| 全站抽奖 | card + row + `lottery__nodata` | card + row + empty | 小 |
| 同屏播放 | `popup-panel__card` + seg + range | card + row + seg + field | 中 |
| 版本更新 | `exupdate-panel__card` + list | card + prose | 小 |

**工作量口径（源码计数）**：`fans-panel__card` 47 处、`sign-option-item` 27、`bloop__` 52、`popup-panel__card` 8、`exupdate-panel__card` 5；内联 style 合计 80+ 处（ExpandTool 一个文件 30）。

### 3.3 旧类名三步退场（不搞大爆炸）

1. **别名期**（现状）：旧类名行为映射到 `.ui-*`，保证未迁移面板不坏；
2. **只读期**：新代码只准用 `ExUI`，旧类名冻结（CI 加一条"旧类名计数不得增加"）；
3. **删除期**：全部面板迁移完成后，一次性删掉别名规则与旧类名。

# 10. 自审（对这份方案的批判性复核）

> 写法：每条都问三个问题 —— ① 这个判断有证据吗？② 如果不成立会怎样？③ 我是不是低估了成本？

## 10.1 站得住的部分

| 结论 | 证据 |
|---|---|
| 「0.62 单层 ≡ 现在 0.617 双层」 | 数值等价：`1-(1-0.34)(1-0.42)=0.617` vs `0.62`；对比度差 0.01 量级，肉眼不可辨 |
| 「统一必须在 DOM 层，CSS 别名是套皮」 | 源码计数：`fans-panel__card` 47 处、`sign-option-item` 27、`bloop__` 52 —— 别名只是让它们"看起来一样"，结构仍是八套 |
| 「白片 0.62 能承载文字」 | 纯黑帧 `#0f172a` 6.66 / `#1e293b` 5.46 / 蓝药丸白字 4.83，全部 ≥4.5 |
| 「跟随网页要用属性选择器」 | 真机取证：`html[data-mantine-color-scheme]`、class 全程不变、cookie 可被同名多域污染导致 5s 回落 |
| 「D2 深色能透到 70%」 | brightness(0.45)+0.30 等效厚度实测 7.35/5.96/4.95/3.33 |

## 10.2 方案里的漏洞（必须先补，否则做完还是"不对"）

| # | 漏洞 | 后果 | 补法 |
|---|---|---|---|
| **A1** | **托盘透明后没给边界**：`.miuix-modal` 只有 1px **白色** 描边 + 阴影，亮画面上等于没有轮廓 | 面板会"糊"进视频里，看着比现在还差 | 托盘补 `0.5px rgba(15,23,42,.16)` 深色切边 + 外阴影加深；白描边降为"内部高光" |
| **A2** | **`--miuix-item-bg` 有 13 处引用**，我只抽查了 6 处 | 若有 1 处不是"白片角色"（比如某个小徽标），M0 会让它莫名变实 | M0 前把 13 处逐个标注角色，列成表格进 PR 描述 |
| **A3** | **分组感会消失**：卡片不再刷白后，"一组设置"只剩间距 | 8 个条目看起来像一长串，找不到分组 | 两个选项：①卡片加 0.5px 分隔虚线（不填充）②组标题与首行之间加 6px 额外间距 —— **要你选** |
| **A4** | **提交按钮锁死 38px**：测试场景 11 硬编码 height:38px/font-size:14px | "命中区 44"只能在关闭钮上做，主按钮做不到；或者改测试 | 建议改测试（把 38 → 44，并同步断言），但这是**动门禁**，需要你点头 |
| **A5** | **ExUI 与 ExUI_stickActionBar 名字挨着** | 后人误以为是一个体系 | 组件对象保持 `ExUI`（无下划线后缀已足够区分），在文件头写清"与 ExUI_stickActionBar 无关" |
| **A6** | **M4 成本可能被低估**：ExpandTool 30 处内联 + BarrageLoop 52 处类名 | 中途卡住，留下"一半新一半旧"的更糟状态 | 两个包**各自独立 commit + 独立回归**；若一批内做不完，允许先"内联清零、类名保留" |

## 10.3 动手前必须先做的 3 个实验（各 30 分钟内）

1. **单层观感实验**：只改两个 token（托盘 `transparent`、白片 `0.62`），不动任何 DOM，出一张面板截图 —— 确认"数值等价但观感更整"。
2. **边界实验**：在实验 1 基础上加 `0.5px` 深色切边，对比亮/暗两帧 —— 确认 A1 的补法够不够。
3. **分组实验**：A3 的两个选项各截一张 —— 你挑一个再写代码。

> 这三个实验不需要迁移任何面板，风险为零，但能把"方案能不能成"从猜测变成看见。

|---|---|---|
| 测试场景 11 | 提交按钮 38px/14px | 见 A4，需授权改测试 |
| 测试场景 11/12 | "一个选择器只能一条规则" | 方案已按此设计（每角色一条 `.ui-*` 规则），但**旧别名规则必须同步删干净**，否则会撞 |

| AGENTS 分支口径 | 大改动 → `DYEXRL-NEXT` | M0/M1 在 NEXT 分支做；验收期不升版本号 |

## 10.5 我对自己这份方案的评分

- **方向对**：从 CSS 别名 → 组件层，是对的，而且是唯一能让"以后新增面板自动一致"的做法。
- **风险被低估的地方**：M0 一次性改全站观感（虽然数值等价），如果用户不接受"单层"的观感，前面所有工作都要回头 —— 所以 10.3 的实验必须先做，**用 5 分钟换掉 5 小时**。
- **最容易翻车的一步**：旧别名与 `.ui-*` 并存期间的"双写"。必须用门禁（旧类名不得增加新样式）挡住，否则又会回到"套皮"。

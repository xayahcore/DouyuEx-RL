## 2. 路线 G2 · 定版取值（全部经 WCAG 计算）

### 2.1 三层结构

| 层 | 取值 | 上面有什么 | 最坏帧（纯黑）依据 |
|---|---|---|---|
| **玻璃壳**（面板外框/缝/Gutter） | **透明** + `blur(28px) saturate(200%)` + 0.5px 深色切边 | 什么都没有（只剩模糊的画面） | 不承担文字对比 |
| **玻璃卡**（卡片/面板头/选项行） | `rgba(255,255,255,0.62)` —— **唯一一层** | 全部文字与开关 | `#0f172a` 6.66 / `#1e293b` 5.46 |
| **Dock 胶囊** | `rgba(255,255,255,0.28)` + 0.5px 深色切边 | 只放图标与指示条 | — |
| **Dock 磁贴** | 有效 `≈0.568`（胶囊 0.28 × 磁贴 0.40）+ 图标 `#0f172a` | 只放图标（图形门槛 3:1） | ≈**5.8:1** |

> **一处自查更正（2026-11-01）**：旧稿标"卡片 0.62 / 透光 38%"是错的 —— 壳 0.34 与卡 0.62 是**叠着**的，等效 `1−(1−0.34)(1−0.62)=0.749`，真透光只有 **25%**。用户指出"Dock 与三级菜单背景上多叠了一层纯白"之后，把壳层改成**透明**：现在卡片才是真的单层 0.62、真 38%，观感也从"白膜"变成"玻璃上浮着瓷片"。白色描边与上沿受光渐变一并去掉，改用 0.5px 深色切边 + 落地阴影定边界。

### 2.2 字与色

| 令牌 | 值 | 用途 | 0.62 玻璃卡 / 纯黑帧 |
|---|---|---|---|
| `--g2-ink-1` | `#0f172a` | 标题、正文 | 6.66 ✓ |
| `--g2-ink-2` | `#1e293b` | 说明文字、元信息、未选中标签 | 5.46 ✓ |
| `--g2-ink-3` | `#334155` | **只允许**放在 ≥0.87 不透明面上 | 3.86 ✗（本档禁用） |
| 品牌蓝 | `#0066ff` | **只作填充**（药丸底、开态轨道、选中图标底） | 蓝底白字 4.83 ✓ |
| 蓝字 | `#0052d9` | 仅用于自带白底的场合 | 对白 5.80 ✓ |
| `#64748b` / `#94a3b8` | **退出文字位** | 只允许在不透明纯白底 | 1.78 / 1.03 ✗ |

> **这一档最需要你点头的代价**：次级文字不能靠"变浅"来分层了（`#475569` 在 0.62 上只有 2.83）。主次改为**字号 + 字重**承担（标题 12.5px/600 / 说明 11.5px/400），颜色只差一档（`#0f172a` vs `#1e293b`）。若你更想保住灰色层级，唯一办法是把卡片提到 **0.70**（透光 30%），那时说明文字可以用回 `#334155`（4.94 ✓）。

### 2.3 开关：**保持现状，本次不动**（用户 2026-11-01 定）

两轮尝试都被否（"肉眼还是有一圈东西"）：先是 4px 白晕，后是 1px 深色内环。**结论：不改开关造型**，沿用 `ExPanel.css:716-781` 现状（轨道 `rgba(0,0,0,.14)` + 白旋钮 + 开态 `#0066ff`）。

唯一保留的改动是**键盘焦点环**（只在 Tab 时出现，静态观感为零）。

> 已知代价，记录在案不作为待办：关态轨道对卡片约 1.2–1.3:1，低于 WCAG 1.4.11 的 3:1。这一条是**知情接受**，不是遗漏。

### 2.4 并行方案 · 路线 D「深色玻璃」（用户指定，与 G2 二选一）

`rgba(16,20,26,0.70)` + 白字：四种画面（黑场/暗帧/亮帧/纯白）下 **6.83–19.34** 全部过 —— 这是**唯一能让文字直接压玻璃**的方案，也是真玻璃最足的一版。

| 令牌 | 值 | 最坏帧（纯白画面） |
|---|---|---|
| `--d-surface`（卡片/头部/行） | `rgba(16,20,26,0.70)` | — |
| `--d-shell`（外壳/Dock 胶囊） | `rgba(16,20,26,0.55)` | 不承载文字 |
| `--d-ink-1` | `#ffffff` | 6.83 |
| `--d-ink-2` | `#e2e8f0` | 5.54 |
| `--d-ink-3` | `#cbd5e1` | 4.60 |
| `--d-accent` | `#7db0ff` | 3.10（只做图标/指示条/≥14px） |
| 药丸底 | `#0066ff` + 白字 | 4.83 |
| 禁用 | `#94a3b8` 做文字 | 2.66 ✗ |

配套：输入框 `rgba(255,255,255,0.08)`、分割线 `rgba(255,255,255,0.10)`、选中磁贴 `rgba(125,176,255,0.18)` + `#7db0ff` 图标、焦点环 `#7db0ff`、开关轨道由"黑 14%"反转为"白 22%"（深底上必须反过来才看得见，造型仍不动）。

**代价**：整套 UI 转深色，与斗鱼亮色页面割裂；品牌蓝要提亮（`#0066ff` → `#7db0ff`），且 `#7db0ff` 在白画面上只有 3.10，**不能用来做小字**。

### 2.5 深色玻璃 v2（D2）—— 用 brightness 归一化，把厚度降到 0.30

用户原话："深色模式还是不够玻璃、不够透"。上一版 D 的问题不是取值保守，而是**方法只有一招**：全靠 alpha 把画面压暗（0.70 → 只透 30%）。真正能让深色玻璃"透而不糊"的是让 **backdrop-filter 自己把背后的画面压暗**：

```css
/* 唯一的 filter 层：模糊 + 压暗都在外壳上发生一次 */
.miuix-modal, .sign-panel, ... {
  background: rgba(16, 20, 26, 0.18);
  backdrop-filter: blur(30px) saturate(130%) brightness(0.45);
}
/* 卡片 / 头部 / 选项行：不再放 filter，只叠很薄一层 tint */
.fans-panel__card, .miuix-modal__header, .livetool__cell, ... {
  background: rgba(16, 20, 26, 0.14);
}
```

等效厚度 = 1 − (1−0.18)(1−0.14) = **0.295 ≈ 0.30**，也就是 **透光 70%**（旧 D 只有 30%）。因为画面被 brightness(0.45) 先压暗，纯白画面也不再刺眼，白字反而更稳：

| 墨色 | 纯白画面（最坏） | 暗帧 | 判定 |
|---|---|---|---|
| `#ffffff` | **7.35** | 19.6 | ✓ |
| `#e2e8f0` | 5.96 | 15.9 | ✓ |
| `#cbd5e1` | 4.95 | 13.2 | ✓ |
| `#7db0ff`（图形/≥14px） | 3.33 | 8.9 | ✓ |

> 另一笔账：filter 层从"1 外壳 + N 卡片"降到**只有外壳 1 层**（Dock 胶囊再 1 层），比现状的 10 层低一个量级 —— 这一版既更透，也更快。

### 2.6 主题三态：白天 / 黑夜 / 跟随网页

**先纠正一个前提**：斗鱼**没有**用户可见的白天/黑夜切换入口。真机取证（376 个 script 全文扫描、21 个 SVG symbol、顶栏/头像菜单/个人中心/播放器设置全部枚举）结论是——库能力存在、UI 入口为零；主题只由一段内联脚本按 **cookie `mantine-color-scheme-value`**（`light|dark|auto`，session 级）写成 `<html data-mantine-color-scheme>`，**没有任何一次写入来自用户点击**。

但它留下的机制是可用的：`<html data-mantine-color-scheme="light|dark">` + 一组 CSS 变量（`--text-color` / `--card-bg` …）真实生效，而且 **`html`/`body` 的 class 全程不变**——所以判据只能用属性，绝不能用 class。据此：

| 项 | 设计 |
|---|---|
| 状态存哪 | `ExSave_theme` = `light` / `dark` / `auto`（新键，遵守 `ExSave_` 前缀） |
| 作用于哪 | `document.documentElement.dataset.dxTheme = light\|dark` + `dataset.dxThemeMode = light\|dark\|auto`，全部样式以 `[data-dx-theme="dark"]` 为前缀，不碰斗鱼自己的 class |
| 「跟随」判据（按优先级） | ① `html[data-mantine-color-scheme]`（首选）② cookie `mantine-color-scheme-value`（`auto` 时斗鱼已折算过系统偏好）③ `body` 计算背景色亮度（<0.2 判黑夜，兜底）④ `prefers-color-scheme` |
| 今天的实际行为 | 斗鱼默认 cookie = `light`，所以第三态今天基本等于"白天"。→ 建议定义成**「跟随（网页优先，网页没给深色就跟系统）」**，否则这个开关点了没反应 |
| 首屏时序 | 实测 119ms 浅色 → 122ms 转深（1 帧闪），另有多域同名 cookie 时 ~5s 二次回落 → **必须监听属性变化，不能只读一次** |
| 可选联动（已验证可行） | 写 cookie `mantine-color-scheme-value=dark` **并派发 `StorageEvent`**，实测 **400ms 内**页面自己转深、background 同步，**不用刷新**；切回写 `light` 复原。→ 黑夜态可以带一个"同时把斗鱼切深"的子开关，从根上消掉割裂感，且切换无闪烁 |
| 何时重算 | `MutationObserver` 只盯 `html` 的 `data-mantine-color-scheme`；另在 `visibilitychange` 与三级面板打开事件上各补一次兜底。**不轮询** |
| **实现关键（取证后修正）** | 「跟随」不做 JS 解析，直接写 **CSS 属性选择器**：`html[data-mantine-color-scheme="dark"][data-dx-theme-mode="auto"] .ex-panel {...}` —— 零 JS、**天生免疫 5s 回落**、切换零延迟。JS 只负责磁贴图标状态与 aria 播报 |
| 不要做什么 | **别读 cookie 判主题**（同名多域 cookie 会让页面 5s 后自己弹回 light，实测 4629/6369/6715ms 三次）；**别用 class 判主题**（`html/body` class 全程不变） |
| 空窗兜底 | 首屏 0–120ms `data-mantine-color-scheme` 还是 `null`（实测 dark 时 119ms 浅色 → 122ms 转深）：默认按白天渲染，DOMContentLoaded 后校正；亮度兜底阈值 0.2（实测 dark 0.0131 / light 0.9223，余量足够） |
| 失效边界 | iframe / 微前端内层 document 无此属性（只读顶层）；`member/cp` 这类不加载内联脚本的页面无属性 → 落到 `prefers-color-scheme` |
| 默认值 | `auto`（用户没说时跟随网页，最省心） |
| 提前量 | 脚本启动时先按 `auto` 探一次，再渲染 Dock，避免"先亮后黑"闪一下 |

**实机证据（已采到）**：`html[data-mantine-color-scheme]` 由 Mantine 写入；`document.body` 背景 `rgb(245,246,250)`、`--text-color: #333`；系统 `prefers-color-scheme: dark` 时斗鱼仍是浅色 —— **说明不能用系统偏好来判断斗鱼的主题**，必须读页面自己的这个属性。

### 2.7.1 层级红线：**只允许一层白**（用户 2026-11-01 定）

用户指出两处"多叠的白"，已按此收敛：

| 位置 | 原来 | 定版 |
|---|---|---|
| Dock 选中态 | 图标填色 **+** 磁贴底色变白 0.92 **+** 蓝框 + 蓝投影 + 上浮 | **只留图标填色 + 底部指示条**（上浮 2px 可选），底色与其它磁贴相同 |
| 三级面板的子项行 | 卡片 0.62 之上，每行再叠一层 0.34 白 + 白描边 | **行 = `rgba(255,255,255,0.42)` + 1px 白边 0.55**（与 Dock 磁贴同一个值）；卡片层改为**透明**的分组容器（只留圆角与间距），否则三层叠起来必然比磁贴更白 |
| 卡片头分隔线 | 1px 白 0.34 | 0.5px `rgba(15,23,42,0.08)` |

规则一句话：**整套只有两个透明度档** ——
- **托盘 0.34**（面板外壳、Dock 胶囊）
- **白片 0.42 + 1px 白边 0.55**（Dock 磁贴、面板头、每一个子项行）

两档叠起来的有效白都是 `1−(1−0.34)(1−0.42)=0.617`，所以磁贴与子项**看起来是同一块白**（浏览器实测：tile `rgba(255,255,255,0.42)`、row `rgba(255,255,255,0.42)`、card `transparent`、head `rgba(255,255,255,0.42)`）。卡片不再是"白层"，只是分组容器。选中态不加白，用图标填色 + 指示条。

## 4. 通透度梯度（备查：为什么是 0.62）

| 档 | 卡片 alpha | 透光率 | 说明文字 | 开关 | 代价 |
|---|---|---|---|---|---|
| G 白瓷 | 0.87 | 13% | `#475569` 5.63 | 保持现状 | 玻璃感弱 |
| **G2**（浅色主推） | **0.62** | **38%** | `#1e293b` 5.46 | 保持现状 | 主次只能靠字重/字号 |
| G3 文字托 | 0.16 | 80% | `#475569`（托上） | 保持现状 | "白漆标签"，且总有漏网的文字 |
| **D 深色玻璃** | 深 0.70 | 30% | 白字 6.83 / 浅灰 4.60 | 轨道反转为白 22%，仍无描边无白晕 | 整套换皮 |
| — 白卡（旧提案） | 0.84 | 16% | `#475569` 5.21 | — | 玻璃感消失（已否） |

所有玻璃档的开关一律**不加白晕、不加描边**（用户 2026-11-01 两轮否决后的统一口径）。

两条硬规律：① 卡片越透底越暗，字必须越深；② 品牌蓝方向随底色反转（浅底要深蓝、深底要亮蓝），所以裸蓝字在通透镜上走不通，蓝只能"自带底"。

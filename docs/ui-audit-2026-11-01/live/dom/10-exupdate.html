版本更新
新增功能
  • • 【工具条】点菜单外面就收：二级胶囊菜单、所有三级面板，以及面板里再开出来的子菜单，只要鼠标点在它们之外，一次全部收起 —— 以前只有右上角那个 × 能关，面板开着占住半屏时还得先找到 ×。
改进与修复
  • • 【工具条】点菜单外面的判定放在鼠标按下那一刻（捕获阶段）：「点外面先收菜单、目标自己的点击再打开新面板」这个顺序天然成立，不会出现刚点开的面板被同一次点击立刻收掉；在面板里按下、拖到外面再松手（框选 / 拖拽）也不算点外面。
  • • 【工具条】只认左键：右键按下不会误收菜单；在面板里按下、拖到外面再松手（框选 / 拖拽）同样不算点外面。
  • • 【工具条】精灵球的「全部收敛」与二级菜单的 × 改走同一个收敛出口：运行期再开出来的子菜单层（礼物选择器、画中画菜单等）也会一并收起；三级面板清单仍然只有一份，新增面板自动纳入判定。
  • • 【工具条】修掉「收起动画没走完就再点精灵球」时点了没反应：160 毫秒的收起动画期间重新展开会真正打开，而不是再收一次。
  • • 【稳定性】修掉一处会让插件整体消失的隐患：构建产物是所有包拼进同一个作用域的一份脚本，只要某个包在自身声明语句执行之前就调到告警函数，计数器就会撞上 TDZ（Cannot access ExGuard_warnCounts before initialization）—— 这条异常没有任何兜底能接，会直接掐断顶层脚本，后面的初始化全部不执行（页面里连精灵球都不出现），日志里却只有一条看不懂的 ReferenceError。现在计数器改为挂在函数属性上惰性创建、上限常量改用 var，顶层提前调用只会照常打一条告警，不再中断脚本。
  • • 【阻止P2P上传】修掉开启后进未开播房间会抛一条未捕获异常（NotSupportedError: WebRTC P2P disabled by user policy）：拦截器的 createOffer / createAnswer 仍然让调用方拿到失败（P2P 起不来），但这个失败 Promise 已经挂好处理器，浏览器不再把它记为「未处理的拒绝」；本地档位被写坏时按「不拦截」处理并留痕，不再让整个包初始化失败。
  • • 【粉丝牌页】房间加载不再白等 10 秒：粉丝牌表格只在独立页或房间内点开浮层后才出现，旧实现每次加载都轮询 20 次、等不到再报一条 warning；现在改成盯 body 子树（400ms 节流），浮层什么时候打开就什么时候接住。
  • • 【赛事聊天室入口】这个节点只在赛事 / 活动房间才有，普通直播间等 10 秒注定空转；补藏逻辑保留，但等不到不再打 warning，只留一条 debug。
  • • 【隐藏礼物栏】删掉已经消失的旧选择器 .right-e7ea5d 的 DomHook（真机 DOM 里命中 0 个，只在每份文档初始化时白发一条「目标不存在」）。

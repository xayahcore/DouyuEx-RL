# 底层梳理方案（2026-11-01 v4）

> ⚠ **历史留档**：2026-11-02 起由 [PLAN.md](PLAN.md) 统一口径。本文件仍有效的部分 = §2 组件契约与 §4 门禁思路；**M0 的表面取值（托盘透明 + 白片 0.62）已作废**，批次顺序也改按 PLAN.md 的 W0–W6。
> 目标修正（用户 2026-11-01）：**保留"面板 → 卡片 → 行"这层嵌套**；本次**不动视觉**，
> 只把底层（DOM 结构 / 类名 / 样式归属 / 内联样式）梳理成一套。
> 判据：迁移前后**像素级观感不变**，但源码里"各干各的"消失。

---

## 0. 为什么"去掉嵌套"会显得乱

上一轮把卡片刷透明、只留行白片之后，底层的问题立刻露出来：

| 现象 | 根因 |
|---|---|
| 八个面板"各自为战" | 同一个"卡片"有 4 个类名、同一个"行"有 3 个类名，样式靠别名硬对齐 |
| 改一处、坏一处 | 面板用内联 `style` 写死字号/颜色（ExpandTool 30 处），CSS 压不住 |
| 结构不一致 | 有的面板是"卡片 > 行"，有的是"卡片 > 表单"，有的是"行本身就是卡片"（直播间工具） |
| 无处下手 | 没有组件层，谁想加一个设置项都得复制粘贴一段模板 |

**结论**：先把"卡片 / 行 / 正文 / 按钮 / 输入"变成**唯一一套 DOM 契约**，嵌套照旧保留，视觉一律不改。

---

## 1. 本次范围（只做这些）

| 做 | 不做 |
|---|---|
| 建立 `ExUI` 组件构造器（唯一 DOM 出口） | 不改任何颜色/圆角/透明度/间距 |
| 建立 `.ui-*` 样式层，**1:1 复刻现状** | 不动玻璃层数、不改选中态观感 |
| 八个面板逐个迁移（DOM 换组件、类名退役） | 不做深色/三态切换（阶段二） |
| 内联样式清零（分面板） | 不动按钮尺寸（测试锁 38px） |
| 门禁：旧类名只减不增、组件契约、单角色一条规则 | 不重构业务逻辑 |

## 2. 底层契约（唯一标准）

### 2.1 结构

```
.miuix-modal                 面板（玻璃托盘，现状不动）
└─ .miuix-modal__header      面板头（现状不动）
└─ .miuix-modal__body
   └─ section.ui-card        分组（不刷白，只分组）
      ├─ .ui-card__head      分组头：title + aside
      └─ .ui-card__body
         ├─ label.ui-row     一条设置项（白片）  → .ui-row__text(.ui-row__title/.ui-row__desc) + 控件
         └─ div.ui-prose     长正文（白片）
```

### 2.2 命名

| 角色 | 类名 | 备注 |
|---|---|---|
| 卡片 | `ui-card` / `__head` / `__title` / `__aside` / `__body` | 一组设置 |
| 行 | `ui-row` / `__text` / `__title` / `__desc` | 一条设置 |
| 正文 | `ui-prose` | 长文本块 |
| 空态 | `ui-empty` | 无数据 |
| 按钮 | `ui-btn` + `--primary`/`--quiet`/`--danger` | 三档 |
| 分段 | `ui-seg` + `ui-seg__item/__label` | 互斥单选 |
| 字段 | `ui-field` + `__label/__control/__hint` | 输入行 |

**旧类名（`fans-panel__card` / `sign-option-item` / `bloop__*` / `livetool__cell` …）只减不增，迁完即删。**

### 2.3 样式归属

- 全部 `.ui-*` 规则写进 `ExPanel.css`（守"UI 改动归口"红线）
- `ExUI.js` 只产 DOM，不含任何颜色/尺寸字面量
- 一个角色只有一个选择器、只有一条规则（仓库测试场景 11/12 已强制这条）

## 4. 门禁（防"又各自为战"）

| 门禁 | 实现 |
|---|---|
| 旧类名只减不增 | `tools/ui-legacy-guard.mjs` 记录基线计数，超基线即失败 |
| 组件契约 | 面板 DOM 里若出现 `.ui-row` 以外的"行"，`?dxdebug=1` 时告警 |
| 单角色一条规则 | 扩展现有 `tests/test_built_bundle.js` 场景 11/12 到 `.ui-*` |
| 内联样式 | 按包计基线，禁止新增 |
| 观感不变 | 迁移前后各截一张（同位置），做像素差比对 |

---

## 5. 与阶段二的关系

阶段二（视觉：单层/双层、深色 D2、主题三态、命中区 44）**等 B1–B8 完成后**再做。
届时只需改 `.ui-*` 的几行 token，不再碰八个面板 —— 这就是"先把底捋顺"的收益。

## 6. 自审

| 风险 | 判断 | 对策 |
|---|---|---|
| 迁移"观感不变"其实做不到 100% | 内联样式清零会带来细微差异（字号/间距） | 逐面板像素比对，差异必须能解释（并写进提交信息） |
| `.ui-*` 与旧别名并存期"双写" | 最容易退回套皮 | 门禁：旧类名不许新增样式；别名只删不改 |
| 迁移影响 JS 绑定 | 行是 `<label>`，里面有 `input`，结构与现在一致 | 保留控件 id/类名，只换外层 |
| 8 个面板一次性做太大 | 中途留下半新半旧 | 一批一个面板、各自提交、各自可回滚 |
